# G1 Support Discontinuity Velocity Design

## Objective

Prevent the support-retargeting spring from manufacturing extreme vertical
velocity when a support target changes discontinuously, without snapping the
rendered pose, changing motion matching, or weakening Task 10 acceptance
thresholds.

## Observed Failure

On `stairs-shallow:ascent-landing-descent`, two adjacent support observations
kept the same `support_airborne_root` source category while their scalar target
changed from approximately `-0.0885 m` to `+0.1600 m`. The current update
differentiated that `0.2485 m` discontinuity over the fixed `0.04 s` step,
creating a nominal velocity of about `6.21 m/s`.

Rebasing the spring with that derivative produced a support-velocity reversal
from roughly `-0.44 m/s` to `+5.21 m/s` and moved support height from about
`+0.001 m` to `-0.135 m` in one frame. This velocity is generated by
`support_frame_update`; it is not a G1 pose velocity or physics result.

## Design

`support_frame_update` will determine discontinuity before estimating nominal
velocity:

```cpp
const float target_delta = target - next.nominal_height;
const bool discontinuity =
    source_changed || std::fabs(target_delta) > 0.02f;
const float target_velocity =
    source == support_held || discontinuity
        ? 0.0f
        : target_delta / dt;
```

For a discontinuity, `support_frame_rebase` will therefore receive the new
nominal height and zero nominal velocity. Its existing offset calculation
continues to preserve the pre-rebase total height and velocity. The existing
spring decay then approaches the new nominal height continuously.

The exact `0.02 m` boundary remains continuous-motion behavior: only a delta
strictly greater than `0.02 m` is a discontinuity. Source-frame or contact
source changes remain discontinuities regardless of target magnitude.

## Invariants

- Fixed update time remains binary32 `0.04 s` at 25 Hz.
- The 31-dimensional matcher, database search, selected frames, trajectory,
  and simulation XZ are unchanged.
- Support still applies once as a downstream world-Y transform.
- Rebasing remains transactional and preserves total height and velocity.
- Finite-input/error handling remains unchanged.
- No velocity clamp, height snap, halflife tuning, threshold relaxation, IK,
  or new runtime option is introduced.

## Tests

Extend `tests/cpp/test_support_runtime.cpp` before changing production code:

1. Reproduce two consecutive same-source discontinuities using the observed
   `-0.0885 m` and `+0.1600 m` targets.
2. Require zero nominal velocity for every above-threshold discontinuity.
3. Require finite height/velocity and no one-frame overshoot outside the
   interval bounded by the prior output and new target.
4. Preserve the existing exact-boundary test: `0.02 m` keeps the sampled
   velocity; the next representable float above it uses zero velocity.
5. Preserve smooth-ramp monotonicity and source/contact transition behavior.

Run the focused test under strict, optimized `-ffast-math`, and ASan/UBSan
builds. Rebuild the controller under `/tmp` and rerun the 800-frame shallow
stairs treatment log to confirm the artificial vertical impulse is absent.

## Scope and Follow-up

This correction addresses only the invalid support derivative. Task 10 may
remain red because stopped-tail matcher loops, terrain/source alignment, Hips
transition continuity, and safe-stop clearance are separate observed product
issues. Those failures must remain visible and must not be hidden by changing
checker thresholds.

Owned implementation files are only `support_runtime.h` and
`tests/cpp/test_support_runtime.cpp`. Existing uncommitted Task 10 checker and
test changes are preserved without modification.
